# NEXA Agent Workspace 项目说明书

| 项目 | 内容 |

## 二、项目背景

传统 AI 问答产品主要解决“生成一段内容”的问题，但知识工作者真正需要的是“完成一项工作”。一个完整的任务通常包含理解目标、查找资料、读取业务数据、调用多个系统、形成交付物、通知协作方和等待人工确认等步骤。

NEXA 将大模型从聊天框升级为可执行任务的智能体工作台。它将 Agent 的规划过程、工具调用和结果交付全部可视化，让用户既能获得自动化效率，也能保留对关键动作的控制和审核。

## 三、目标用户与痛点

### 目标用户

- 需要高频输出周报、复盘和运营分析的业务人员。
- 需要跟踪竞品、客户反馈和市场变化的产品与市场团队。
- 需要将会议结论转化为行动项的项目管理者。
- 希望把内部系统与 AI 能力连接起来的企业开发者。

### 核心痛点

1. 信息散落在知识库、业务系统、消息工具与个人经验中。
2. 普通聊天机器人不能读取实时数据，也不能真正执行后续动作。
3. 自动化平台学习成本高，业务人员难以独立搭建流程。
4. AI 输出过程不透明，关键结论缺少来源和运行轨迹。
5. 涉及发送、创建任务等动作时，需要人工审核与权限边界。

## 四、产品定位

NEXA 的定位是“可观测的企业级 AI Agent 工作台”。它不是单一聊天页面，也不是纯可视化流程图，而是将智能对话、任务编排、工具连接、企业知识和运行观测整合到同一个产品闭环中。

产品强调三个原则：

- **目标优先**：用户描述“要完成什么”，Agent 自行选择执行路径。
- **过程可见**：规划、工具、知识来源、状态和耗时均可追溯。
- **关键可控**：写操作前保留权限边界和人工审核入口。

## 五、核心使用场景

### 场景一：运营周报自动生成

用户输入“生成本周产品运营周报”。Agent 自动完成：

1. 解析周报受众、周期和交付标准。
2. 调用项目指标工具读取活跃团队、激活率、留存率和渠道数据。
3. 检索增长运营手册和客户反馈知识。
4. 识别增长亮点、留存风险和下周行动建议。
5. 生成结构化周报，并创建后续专项任务。

该场景同时展示自主规划、工具调用、知识检索、结果生成和任务创建。

### 场景二：竞品动态扫描

用户要求分析近期 AI Agent 竞品动态。Agent 检索市场情报与客户洞察，输出竞争方向、机会判断和行动建议，并给出来源文档。

### 场景三：会议行动项整理

Agent 从会议上下文中提炼决策、行动项、负责人和截止时间，在用户确认后创建后续任务或发送通知，形成“整理 → 审核 → 执行”的闭环。

### 场景四：客户反馈聚类

Agent 将客户原声聚类为主题，识别高频问题、情绪趋势和产品机会，并将结果沉淀到知识库，供后续 Agent 复用。

## 六、功能设计

### 1. Agent 工作台

- Agent 团队卡片：状态、本月运行、准确率、能力概述。
- 任务命令行：支持自然语言目标输入和快捷任务。
- 实时执行面板：展示当前运行节点、进度和耗时。
- 效率指标：活跃 Agent、自动化任务、成功率、节省时间。
- 自动化工坊与最近动态：快速进入工作流和运行记录。

### 2. 智能对话

- 多轮上下文：同一次会话内保持历史和任务状态。
- 执行计划：按步骤展示 Agent 的处理路径。
- 工具调用记录：名称、结果摘要、成功或失败状态。
- 知识来源：每条结论可回到企业内部文档。
- 结果操作：复制、重新生成、转为任务。
- 运行控制：执行中可停止，避免不可控等待。

### 3. 任务中心

- 四阶段看板：待处理、进行中、等待审核、已完成。
- 任务负责人、Agent、截止时间和执行进度。
- 审核操作：人工确认后继续后续动作。
- 任务转化为工作流执行，形成从目标到交付的完整闭环。

### 4. 可视化工作流

- 六节点运营周报模板：触发器、任务规划、知识检索、质量校验、生成交付物、发送通知。
- 节点拖拽、画布缩放和小地图。
- 节点配置：名称、说明、模型、超时、失败重试、人工审核。
- 运行动画：逐节点显示执行状态，并写入运行历史。
- 执行日志：记录节点完成情况和耗时。

### 5. 企业知识库

- 文档分类：策略、产品、市场、客户洞察、制度规范。
- 文档检索、负责人、更新时间、分块数和引用次数。
- 文档详情与内容预览，突出 Agent 使用建议。
- 支持上传 PDF、Office、TXT、Markdown、CSV 文件。

### 6. 工具连接

- 飞书、企业微信、Notion、GitHub、Webhook、自定义 REST API。
- 连接状态、授权账户、启用与暂停。
- 调用上限、写操作确认、返回内容记录等安全设置。
- 通过 OpenAPI Schema 扩展企业私有工具。

### 7. 运行记录

- 运行总数、成功率、平均耗时、异常运行。
- 按成功、运行中、待审核、失败筛选。
- 展开查看执行轨迹、运行摘要、导出和重新运行。
- 关键异常可定位到具体工具步骤。

## 七、界面设计

视觉方向采用“安静的智能工作台”：

- 深墨绿侧栏建立企业级控制感，暖灰背景降低长时间使用的视觉疲劳。
- 薄荷绿代表 Agent 能力与正常运行，珊瑚色表示执行中的任务，蓝色和紫色用于知识与模型能力。
- 页面以信息密度和可扫描性优先，避免营销式大标题与装饰性卡片堆叠。
- 所有工具按钮使用统一线性图标；状态使用颜色、文字和点状信号共同表达。
- 桌面端提供完整三栏协作界面，移动端收拢为单栏和抽屉导航。

## 八、项目创新点

1. **Agent 过程可视化**：不只展示最终文本，还展示计划、工具、来源和状态。
2. **对话与工作流一体化**：对话用于探索任务，工作流用于稳定复用。
3. **运行可观测**：把 Token、耗时、异常与节点轨迹纳入产品核心界面。
4. **演示模式降级**：比赛现场无网络或未配置 Key 时仍能完整展示产品。
5. **写操作安全边界**：发送通知、创建任务等动作显式可见并支持人工审核。
6. **企业知识优先**：回答优先引用内部知识，不依赖不可验证的模型记忆。

## 九、项目完成度

当前版本已实现可直接演示的完整 Web 产品：

- 七个一级页面可切换，核心按钮均有反馈或真实状态变化。
- 对话可调用服务端 Agent API，并展示规划和工具轨迹。
- 工作流可运行、配置节点、添加节点并写入运行记录。
- 工具开关、文档上传、任务状态流转、运行详情展开均可交互。
- 桌面与移动端通过 Playwright 自动验收。
- 提供真实大模型接入方式与本地演示降级模式。
