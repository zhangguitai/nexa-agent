## 七、现场演示流程

1. 执行 `npm run dev`。
2. 打开 `http://localhost:4173`。
3. 展示工作台与 Agent 团队。
4. 在智能对话中输入或点击“生成运营周报”。
5. 展示执行计划、工具轨迹和知识来源。
6. 打开工作流并运行，观察节点推进。
7. 在任务中心点击审核，展示人工闭环。
8. 打开知识库和工具连接，展示企业能力接入。
9. 打开运行记录，展示完整可观测性。
10. 缩小浏览器到移动端尺寸，展示响应式布局。

## 八、风险与应对

| 风险 | 应对 |
| --- | --- |
| 现场没有网络 | 未配置 Key 自动进入本地演示模式 |
| 模型接口超时 | 服务端 35 秒超时并自动降级 |
| 模型厂商不同 | 使用 OpenAI 兼容接口，可配置 Base URL、Model 和 Key |
| 工具调用失败 | 失败结果回传模型，前端显示错误状态 |
| 作品被误认为静态页面 | 展示真实 `/api/agent/run` 请求、工具轨迹和工作流运行 |
| 移动端展示不稳定 | 使用 390 × 844 视口完成自动化验收 |
| 浏览器缓存旧代码 | 服务端 HTML 使用 `no-cache`，演示前刷新页面 |

## 九、答辩要点

### 1. 为什么使用原生前端？

比赛现场最重要的是稳定运行。原生 Web 前端没有安装依赖和构建步骤，同时仍保留组件化模板、状态管理、响应式布局和完整交互。Agent 能力由 Node 服务端真实实现，不因前端轻量而变成纯静态页面。

### 2. Agent 与普通聊天机器人有什么区别？

普通聊天机器人主要输出文本。NEXA Agent 会理解目标、拆解步骤、调用知识与企业工具、创建任务、发送通知，并展示完整执行轨迹。用户还可以把一次性对话沉淀为可复用工作流。

### 3. 如何避免模型编造？

系统提示词要求涉及内部事实时优先调用工具；回答中展示知识来源；工具结果会回传模型再次生成；运行记录保留每次调用状态。

### 4. 写操作如何保证安全？

工具采用白名单定义，写操作只能通过 `create_follow_up` 和 `send_notification` 执行。提示词要求用户明确指令，产品界面提供人工审核节点和连接权限配置。

### 5. 如何证明项目不是只做了界面？

启动服务后，前端会真实请求 `/api/agent/run`。配置 Key 后，服务端会调用大模型并根据 `tool_calls` 执行工具，再将结果回传模型完成最终回答。没有 Key 时，服务端也使用相同响应结构返回演示结果。

### 6. 如何扩展到真实企业系统？

将知识检索替换为向量数据库，将指标工具替换为数据仓库 API，将任务工具替换为飞书任务或 Jira，将通知工具替换为飞书机器人或企业微信应用即可，Agent 循环和前端可观测结构保持不变。
