# Agent 提示词与工具定义

本文档记录 NEXA Agent 的服务端提示词、工具定义和执行约束，便于评审理解项目的模型能力，也便于后续替换为企业模型。

## 一、系统提示词

```text
你是 NEXA Agent，一名服务企业知识工作者的智能执行助理。
你的目标不是只回答问题，而是自主完成用户交付的任务。工作原则：
1. 先理解目标、约束与期望交付物，再决定步骤。
2. 涉及企业内部事实、产品数据、市场情报时，必须调用提供的工具，不要编造。
3. 工具调用失败时说明影响，并给出可执行的替代方案。
4. 最终回答使用简洁中文。优先给出结论、关键数据、风险与下一步，不展示隐藏思维过程。
5. 只在用户明确要求推进或发送时调用写操作工具。
6. 不要声称执行了工具未返回的动作。
```

提示词的设计重点：

- 将 Agent 的角色从“问答”转为“执行”。
- 将企业事实与模型记忆分离。
- 明确失败处理与写操作边界。
- 要求输出可读结论，不暴露内部推理过程。

## 二、工具注册

### 1. 企业知识检索

```json
{
  "name": "search_knowledge",
  "description": "在企业知识库中检索制度、产品说明、市场情报和客户洞察。回答涉及内部事实时应优先调用。",
  "parameters": {
    "query": "检索关键词或问题",
    "limit": "返回条数，1-5"
  }
}
```

返回：

```json
{
  "ok": true,
  "query": "运营周报",
  "results": [
    {
      "id": "kb-growth-playbook",
      "title": "2026 Q4 增长运营手册",
      "type": "策略文档",
      "content": "Q4 北极星指标与增长抓手..."
    }
  ],
  "count": 1,
  "detail": "命中 1 篇企业知识"
}
```

### 2. 项目指标读取

```json
{
  "name": "get_project_metrics",
  "description": "读取产品运营仪表盘中的实时指标，包括活跃团队、激活率、留存和渠道数据。",
  "parameters": {
    "scope": "product 或 growth"
  }
}
```

返回包含：

- 活跃团队与环比变化。
- 激活率与变化。
- 周留存率与变化。
- 主要渠道与占比。

### 3. 创建后续任务

```json
{
  "name": "create_follow_up",
  "description": "在任务中心创建一个可追踪的后续行动。仅当用户要求推进、安排或创建任务时调用。",
  "parameters": {
    "title": "行动标题",
    "owner": "负责人",
    "due": "截止日期"
  }
}
```

该工具属于写操作。服务端返回任务 ID、负责人、截止时间和 pending 状态。

### 4. 发送协作通知

```json
{
  "name": "send_notification",
  "description": "将最终结果发送到指定协作渠道。执行前应确保用户明确要求发送。",
  "parameters": {
    "channel": "feishu、wecom 或 email",
    "summary": "发送内容摘要"
  }
}
```

该工具属于写操作。产品设计将发送动作放在工作流末端，并可配置人工审核。

## 三、工具调用循环

```text
模型第一次响应
  → 返回 1 至 N 个 tool_calls
  → 服务端逐个执行白名单工具
  → 将 tool result 写回 messages
  → 再次调用模型
  → 模型生成最终回答
```

约束：

- 最多四轮。
- 单次模型调用 35 秒超时。
- 请求体最大 1 MB。
- 消息最长 12,000 字符。
- 未知工具返回错误，不执行任意代码。

## 四、规划展示

服务端不要求模型输出隐藏思维链，而是根据实际工具轨迹生成高层执行计划：

```text
理解目标与交付标准
读取项目指标
企业知识检索
创建后续任务
校验结果并生成交付物
```

这种设计既能让评委和用户理解 Agent 的执行路径，也避免暴露模型内部推理过程。

## 五、演示模式

未配置 `LLM_API_KEY` 时，服务端使用关键词和预置知识生成响应：

- 周报任务：读取指标 → 检索知识 → 创建任务。
- 竞品任务：检索市场情报 → 输出机会判断。
- 会议任务：检索产品上下文 → 创建行动项。
- 通用任务：知识检索 → 给出执行建议。

演示模式返回与真实模型相同的结果结构，因此前端交互和工作流体验保持一致。

## 六、模型兼容性

服务端通过以下配置连接 OpenAI 兼容接口：

```dotenv
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
LLM_API_KEY=your_api_key
```

也可替换为：

- OpenAI 官方接口。
- DeepSeek。
- 通义千问兼容模式。
- 企业私有 OpenAI 兼容网关。

只要接口支持 `/chat/completions` 和 `tools` 参数即可使用完整 Agent 循环。
